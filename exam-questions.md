## 5. Github Workflow

What are the steps of the Github workflow. Why is each step included?

(answer here): Fork-Clone-Test-make an issue report-merge-push

The reason it is like this is so first you create a copy of the Repo with Fork, the Clone allows you to modify it without breaking anything on the main Repo, testing lets you fiddle around and make changes, and when you have a change you like, or fixed something that was bothering you, you then create the issue report and merge it (assuming you have ownership), then you can push it all to Git to your forked Repo.
